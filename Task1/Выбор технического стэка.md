**Решение**

## Выбор LLM-модели

🆚 Модели: Hugging Face vs облачные OpenAI vs YandexGPT

Критерии сравнения
- качество ответов
- скорость работы
- стоимость владения и использования
- удобство и простота развёртывания

|                                          | качество ответов | скорость работы   | стоимость владения и использования | удобство и простота развёртывания              |
| ---------------------------------------- | ---------------- | ----------------- | ---------------------------------- | ---------------------------------------------- |
| **OpenAI <br>(GPT-4o)**                  | ⭐⭐⭐              | ⭐⭐⭐<br>≥ 800 ms   | 💲💲💲<br>cloud                    | 🧠<br>API key + SDK                            |
| **YandexGPT Pro**                        | ⭐⭐⭐              | ⭐⭐<br>≥ 1000 ms   | 💲💲<br>cloud                      | 🧠                                             |
| **Hugging Face<br>(Llama 3, Mixtral)** ✅ | ⭐⭐               | ⭐⭐⭐<br>SLA – cost | 💲💲<br>on-perm                    | 🧠🧠🧠<br>Llama, Kubernetes, TLS, Obsevability |

Оценка стоимости владения
```text
on-perm = GPU_аренда + devops + monitoring + security
cloud = Цена_за_token × Объём
```

**Особенности**
* **OpenAI** — самый быстрый, дорогой, простой в использовании
* **YandexGPT** — оптимизирован русского языка, средняя цена, простой в использовании
* **Hugging Face** — самый гибкий в настройке, максимальный контроль на моделью, более сложная настройка.

**Вывод** ✅
Для прикладной задачи оптимальным выбором будет **Hugging Face** т.к.:
* возможность дообучения модели
* оптимальная гибкость настройки для прикладной задачи
* контроль на latency и ценой владения за счет on-perm решения

## Выбор модэмбеддингов

🆚 Эмбеддинги: Sentence-Transformers vs OpenAI text-embedding

Критерии сравнения
- скорость создания индекса
- качество поиска
- стоимость владения и использования

|                                           | скорость создания индекса <br>(эмбеддинги/сек) | качество поиска                                             | стоимость владения и использования                         |
| ----------------------------------------- | ---------------------------------------------- | ----------------------------------------------------------- | ---------------------------------------------------------- |
| all-MiniLM-L6-v2                          | ≥2K                                            | ⭐⭐<br>- тексты до 512 токенов<br>+ Fine-tuning              | `$0 / 1M input tokens`<br>`Аренда GPU: $0.5–$2/hour`       |
| OpenAI text-embedding-3                   | ≥8K                                            | ⭐⭐<br>+ тексты до 8192 токенов<br>- нет Fine-tuning         | `$0.20 / 1M input tokens`                                  |
| intfloat/multilingual-e5-large-instruct ✅ | ≥2K                                            | ⭐⭐<br>- тексты до 512 токенов<br>+ поддержка русского языка | `$0 / 1M input tokens`<br>+ Не требует GPU<br>+ On-permise |

**Особенности прикладной задачи**
- База знаний представляет собой 85 историй
- Каждая история ~4000 символов, ~ 500–600 токенов
- Все тексты на русском языке
- Размер словаря, ~5300 уникальных слов, тексты довольно однородные

**Требования к системе**
- Локальный запуск
- On-perm система: Intel Core i5, 16 BG RAM, No-GPU
- Контекст ≥ 512 токенов
- бесплатная лицензия

**Решение** ✅

Для прикладной задачи оптимальным выбором будет **intfloat/multilingual-e5** т.к.:
* Бесплатная
* Поддержка русского языка
* Оптимальное потребление ресурсов под систему
	* Прогноз потребления ресурсов
		* до 3 GB RAM
		* до 2 сек на разбор документа 4000 символов
* Размер контекста (512 токенов) сопоставим с размером документ (до 600 токенов)
* **Sentence-Transformers** — можно дообучить под конкретный бизнес

## Выбор системы хранения 

🆚 Системы хранения: ChromaDB vs FAISS

Критерии сравнения
- скорость поиска и индексации
- сложность внедрения и поддержки
- удобство в работе
- стоимость владения (учёт инфраструктуры)


|              | скорость поиска и индексации | сложность внедрения и поддержки | удобство в работе | стоимость владения (учёт инфраструктуры)                |
| ------------ | ---------------------------- | ------------------------------- | ----------------- | ------------------------------------------------------- |
| ChromaDB<br> | ≤ 50 ms                      | 🧠<br>проще                     | ⭐⭐⭐<br>~ mongoDB  | 💲 : `CPU`<br>выгоднее для MVP                          |
| FAISS ✅      | ≤ 5 ms <br>при GPU с CUDA    | 🧠🧠<br>умеренная сложность     | ⭐⭐⭐<br>~ numPY    | 💲💲 : `GPU + DevOps` <br>выгоднее на больших нагрузках |
- Chroma — **полный сервер поиска**
	- Векторная база данных
- FAISS — **библиотека для ближайшего соседа**
	- поддержка GPU

**Решение** ✅
Для прикладной задачи оптимальным выбором будет **ChromaDB** т.к. 
* подходит для MVP
* позволяет хранить текст + метаданные + эмбеддинги
